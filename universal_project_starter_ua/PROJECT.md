# PROJECT

Це головний файл проєкту. Він пояснює, що ми будуємо, для кого, навіщо і коли першу версію можна вважати завершеною.

## 1. Project Name

Telegram Calendar Bot

## 2. Project Summary

Telegram Calendar Bot — це Telegram-бот, у який користувач надсилає текстове повідомлення з подією, а бот перетворює його на нагадування в локальному календарі.

Бот підтримує просту природну мову, уточнює дату, час або назву події, якщо інформація неповна, зберігає події в SQLite і надсилає локальні нагадування у потрібний момент. Голосові повідомлення через Whisper залишаються наступним етапом після стабілізації текстового MVP.

Google Calendar не входить у MVP і буде окремим етапом після стабілізації базового сценарію.

## 3. Problem

Яку проблему вирішує проєкт?

```text
Користувачу незручно щоразу відкривати окремий календар або форму, щоб швидко записати подію чи нагадування.

Проєкт вирішує це через Telegram: користувач просто пише повідомлення, а бот допомагає перетворити його на подію з нагадуванням.

Основна мета MVP — зробити запис подій максимально швидким і простим.
```

## 4. Target User

Хто буде користуватися продуктом?

```text
Перший користувач — автор проєкту.

Також бот може використовуватися кількома тестовими користувачами для перевірки сценаріїв, помилок і зручності.

Потенційно продукт корисний для:
- людей, які активно користуються Telegram;
- студентів;
- фрилансерів;
- невеликих команд або приватного використання;
- користувачів, яким потрібні швидкі нагадування без окремого календарного застосунку.
```

## 5. Value

Яку цінність отримує користувач?

```text
Користувач отримує простий спосіб створювати події та нагадування прямо в Telegram.

Цінність MVP:
- менше ручних дій;
- швидке створення події з тексту;
- зрозуміле підтвердження перед збереженням;
- локальні нагадування у потрібний час;
- базовий контроль над власним розкладом без додаткових застосунків.
```

## 6. MVP Scope

Мінімальна версія, яка вже дає користь.

```text
- Telegram-бот працює через aiogram.
- Бот приймає текстові повідомлення від користувача.
- Бот підтримує просту природну мову для подій, наприклад "завтра о 15:00 зустріч".
- Голосові повідомлення не входять у поточний text-first MVP і залишаються backlog-напрямом.
- Бот уточнює дату, час або назву події, якщо вони відсутні або неоднозначні.
- Бот показує користувачу попередній перегляд події перед збереженням.
- Бот зберігає події в SQLite.
- Бот зберігає часовий пояс користувача.
- Бот показує список найближчих подій.
- Бот дозволяє видалити подію.
- Бот надсилає локальні нагадування через APScheduler.
- Бот має команди /start, /help, /whoami, /timezone, /confirm, /cancel, /list і /delete.
- Додавання події доступне через кнопку Додати подію і через звичайне текстове повідомлення з описом події.
- Є базова локальна інструкція запуску.
```

## 7. Out of Scope

Що точно не входить у першу версію?

```text
- Google Calendar інтеграція.
- Платна підписка або монетизація.
- Командні календарі.
- Веб-адмінка.
- Мобільний застосунок.
- Повноцінна система ролей і прав доступу.
- Складний NLP або повноцінний AI-асистент для планування.
- Багатокалендарна модель.
- Повторювані події.
- Публічний реліз для великої кількості користувачів.
```

## 8. Success Criteria

Проєкт або етап вважається завершеним, коли:

- [ ] Бот запускається локально без помилок.
- [ ] Працює команда /start.
- [ ] Працює команда /help.
- [ ] Користувач може створити подію з тексту.
- [ ] Голосові повідомлення через Whisper підтверджені як наступний етап після text-first MVP.
- [ ] Бот зберігає події в SQLite.
- [ ] Бот показує список подій.
- [ ] Бот дозволяє видалити подію.
- [ ] Бот надсилає нагадування у правильний час.
- [ ] Часовий пояс користувача зберігається окремо.
- [ ] Є базова документація.
- [ ] Є тестові сценарії.
- [ ] Секрети не зберігаються в коді.
- [ ] Немає Critical/High bugs для основного сценарію.

## 9. Constraints

Обмеження проєкту:

```text
- Budget: мінімальний; бажано безкоштовні або локальні рішення для MVP.
- Deadline: немає жорсткого дедлайну.
- Preferred technologies:
  - Python;
  - aiogram;
  - Whisper для speech-to-text;
  - SQLite;
  - APScheduler;
  - python-dotenv або pydantic-settings;
  - pytest.
- Forbidden technologies:
  - платні сервіси без потреби для MVP;
  - складні enterprise-рішення;
  - зберігання секретів у коді;
  - Google Calendar у MVP.
- Hosting limits:
  - спочатку локальний запуск;
  - далі простий дешевий або безкоштовний хостинг;
  - без складної інфраструктури на старті.
- Privacy requirements:
  - Telegram Bot Token тільки в .env;
  - особисті події не мають бути видимими іншим користувачам;
  - не логувати токени, ключі, приватні повідомлення без потреби;
  - база даних не має потрапляти в git.
```

```text
    ↓

    ↓

```

## 12. First Development Milestones

```text
Milestone 1: Project bootstrap
- створити базову структуру проєкту;
- налаштувати конфігурацію та .env;
- підняти локальний Telegram-бот.

Milestone 2: Text event flow
- додати /start та /help;
- створити діалог додавання події;
- розпізнавати просту природну мову;
- підтверджувати подію перед збереженням.

Milestone 3: SQLite storage
- зберігати користувачів, події та часові пояси;
- показувати список подій;
- видаляти події.

Milestone 4: Voice flow
- приймати voice message;
- завантажувати аудіо з Telegram;
- розпізнавати текст через Whisper;
- обробляти результат так само, як звичайний текст.

Milestone 5: Reminder system
- запланувати локальні нагадування;
- надсилати повідомлення у потрібний час;
- обробляти перезапуск бота без втрати подій.

Milestone 6: Cleanup and documentation
- перевірити основні сценарії;
- оновити README;
- підготувати MVP до наступного етапу.
```
