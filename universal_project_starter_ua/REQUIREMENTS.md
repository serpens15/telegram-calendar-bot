## 2. Non-Functional Requirements

Нефункціональні вимоги - це якість системи.

### Security

- Секрети зберігаються тільки в `.env`.
- Токени, паролі й ключі не потрапляють у git.
- Користувацький input валідовується.

### Reliability

- Система не падає від некоректного input.
- Помилки логуються зрозуміло.
- Критичні операції мають fallback або зрозумілу помилку.

### Performance

- Система відповідає достатньо швидко для MVP.
- Немає очевидних зайвих запитів або важких операцій.

### Maintainability

- Код розбитий на зрозумілі модулі.
- Бізнес-логіка не захована в UI або handler-ах.
- Коментарі додаються тільки там, де вони справді потрібні.

### Scalability

- Архітектура не повинна ускладнювати MVP.
- Але не треба блокувати очевидний майбутній розвиток.
