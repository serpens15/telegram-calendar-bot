# REQUIREMENTS

Цей файл описує, що система має робити і якою вона має бути.

Проєкт: **Telegram Calendar Bot**  
Тип продукту: **Telegram-бот для створення подій через текст і голос**  
Стадія: **MVP**  
Основна ціль: користувач пише або надсилає голосове повідомлення, бот перетворює його на подію, зберігає в SQLite та нагадує у потрібний час.

## 1. Functional Requirements

Функціональні вимоги — це конкретні можливості продукту.

```text
FR-001: Користувач може запустити бота командою /start.
FR-002: Бот має показати коротку інструкцію після /start.
FR-003: Користувач може запросити довідку командою /help.
FR-004: Користувач може створити подію через команду /add.
FR-005: Користувач може створити подію звичайним текстовим повідомленням.
FR-006: Система має підтримувати просту природну мову, наприклад "завтра о 15:00 зустріч".
FR-007: Система має розпізнавати дату, час і назву події.
FR-008: Якщо дата, час або назва не визначені однозначно, бот має поставити уточнювальне запитання.
FR-009: Якщо подія розпізнана, бот має показати попередній перегляд перед збереженням.
FR-010: Користувач може підтвердити або скасувати створення події.
FR-011: Система має зберігати подію в SQLite.
FR-012: Користувач може переглянути список найближчих подій командою /list.
FR-013: Користувач може видалити подію командою /delete.
FR-014: Користувач може скасувати поточний сценарій командою /cancel.
FR-015: Користувач може встановити або змінити часовий пояс командою /timezone.
FR-016: Система має зберігати часовий пояс користувача окремо.
FR-017: Система має надсилати нагадування перед подією.
FR-018: Користувач може змінити стандартний час нагадування або використати значення за замовчуванням.
FR-019: Бот має приймати голосові повідомлення.
FR-020: Голосові повідомлення мають перетворюватися на текст через Whisper.
FR-021: Після транскрибації голосове повідомлення має проходити той самий сценарій, що й текст.
FR-022: Бот має працювати тільки для дозволених користувачів на MVP-етапі.
FR-023: Адміністратор може додавати дозволені Telegram ID.
FR-024: Бот має обробляти помилки транскрибації, парсингу, бази даних і планувальника без падіння процесу.
```

## 2. Non-Functional Requirements

Нефункціональні вимоги — це якість системи.

### Security

- Секрети зберігаються тільки в `.env`.
- Telegram bot token, Whisper credentials та інші ключі не потрапляють у git.
- `.env` не комітиться.
- Користувацький input валідовується перед обробкою.
- На MVP доступ мають тільки дозволені Telegram ID.
- Логи не містять токенів, секретів або приватних повідомлень без потреби.

### Reliability

- Система не падає від некоректного input.
- Якщо дата або час не розпізнані, бот просить уточнення.
- Якщо Whisper недоступний або транскрибація провалилася, бот повідомляє про помилку.
- Якщо SQLite недоступна, бот показує зрозумілу помилку й не створює частковий запис.
- Якщо APScheduler не може запланувати нагадування, подія не вважається повністю завершеною без повідомлення про проблему.
- Після перезапуску бот має відновлювати активні нагадування з бази.

### Performance

- Бот відповідає на звичайні команди протягом кількох секунд.
- Транскрибація голосу може займати довше, але має бути явно повідомлена користувачу.
- Немає зайвих повторних запитів до бази або Whisper.
- Планувальник не має перевіряти події частіше, ніж потрібно для MVP.

### Maintainability

- Код розбитий на окремі модулі: handlers, services, repositories, scheduler, config.
- Telegram handlers не містять бізнес-логіку.
- Обробка тексту, транскрибація і робота з базою розділені.
- Назви файлів, функцій і змінних мають бути зрозумілими.
- Логіка додавання події не дублюється для тексту і голосу.

### Scalability

- Архітектура не ускладнює MVP.
- Додати Google Calendar після MVP має бути можливо без переписування ядра.
- Додати кількох користувачів має бути можливо через існуючу модель даних.
- Додати повторювані події можна буде окремим етапом.

## 3. User Stories

```text
US-001:
Як користувач, я хочу написати подію природною мовою, щоб швидко створити нагадування без окремих форм.

Acceptance Criteria:
- [ ] Бот приймає текст типу "завтра о 15:00 зустріч".
- [ ] Бот розпізнає дату, час і назву.
- [ ] Бот показує попередній перегляд перед збереженням.
```

```text
US-002:
Як користувач, я хочу надіслати голосове повідомлення, щоб не друкувати подію вручну.

Acceptance Criteria:
- [ ] Бот приймає voice message.
- [ ] Аудіо транскрибується через Whisper.
- [ ] Розпізнаний текст проходить той самий сценарій, що й звичайний текст.
```

```text
US-003:
Як користувач, я хочу підтвердити подію перед збереженням, щоб уникнути помилок.

Acceptance Criteria:
- [ ] Бот показує назву, дату, час і часовий пояс.
- [ ] Користувач може підтвердити або скасувати створення.
- [ ] Подія зберігається тільки після підтвердження.
```

```text
US-004:
Як користувач, я хочу переглянути список найближчих подій, щоб контролювати свій розклад.

Acceptance Criteria:
- [ ] Команда /list показує найближчі події.
- [ ] Якщо подій немає, бот повідомляє про це.
- [ ] Список показується у зрозумілому форматі.
```

```text
US-005:
Як користувач, я хочу видалити подію, щоб прибрати непотрібний запис.

Acceptance Criteria:
- [ ] Команда /delete запускає сценарій видалення.
- [ ] Користувач може вибрати подію зі списку.
- [ ] Бот просить підтвердження перед видаленням.
- [ ] Подія видаляється після підтвердження.
```

```text
US-006:
Як користувач, я хочу отримувати нагадування у потрібний час, щоб не забути про подію.

Acceptance Criteria:
- [ ] Бот надсилає нагадування перед подією.
- [ ] Час нагадування береться із стандартного значення або налаштування користувача.
- [ ] Повідомлення нагадування містить назву події, дату й час.
```

```text
US-007:
Як користувач, я хочу встановити часовий пояс, щоб події і нагадування працювали коректно.

Acceptance Criteria:
- [ ] Команда /timezone дозволяє встановити timezone.
- [ ] Часовий пояс зберігається в базі.
- [ ] Усі події та нагадування використовують timezone користувача.
```

```text
US-008:
Як адміністратор, я хочу обмежити доступ до бота, щоб на MVP ним користувалися лише дозволені люди.

Acceptance Criteria:
- [ ] Система перевіряє Telegram ID.
- [ ] Дозволені користувачі мають доступ.
- [ ] Недозволені користувачі отримують повідомлення про обмежений доступ.
```

## 4. Edge Cases

```text
- Порожнє повідомлення:
  Бот просить ввести текст події або скористатися /help.

- Невідомий формат дати або часу:
  Бот просить уточнити дату чи час і дає приклад.

- Подія вже в минулому:
  Бот відхиляє створення та пропонує майбутню дату.

- Природна мова не дає впевненого результату:
  Бот ставить уточнювальне запитання замість збереження.

- Голосове повідомлення не розпізнано:
  Бот повідомляє про помилку транскрибації й пропонує повторити.

- Whisper недоступний:
  Бот повідомляє, що голосову обробку тимчасово неможливо виконати.

- SQLite недоступна:
  Бот показує технічну помилку і не завершує роботу аварійно.

- Дубль події:
  Бот попереджає про можливий дубль і просить підтвердити створення.

- Користувач скасовує дію:
  Бот очищає тимчасовий стан сценарію.

- Користувач не має доступу:
  Бот повідомляє про обмежений доступ і завершує діалог.

- Часовий пояс не встановлено:
  Бот використовує значення за замовчуванням і просить встановити його пізніше.

- APScheduler не запустив задачу:
  Бот логуватиме помилку і повторно відновлюватиме нагадування після рестарту.
```
